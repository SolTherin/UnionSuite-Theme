For authors: keep the class in the iPart's CSS class field and use only the supplied inner template. In a Query Template Display, that template repeats once per record; the generated class wrapper encloses the whole iPart. Moving the class into each result will not repair outer-shell detection.

Selector and preview rules For theme maintainers

.ContentItemContainer > .panel covers only the direct form. Support both the direct panel and .ContentItemContainer > div > .panel, then validate the component's own native contents. Keep header/body selectors relative to that panel's immediate owner. A blanket .ContentItemContainer .panel selector can also style nested iParts and CCO panels.

Runtime markers and header-action class lookup belong on the matched immediate owner. Preview generators must reproduce the added div, not put the class on ContentItemContainer or supply runtime attributes in advance. Check direct, configured-class, empty-wrapper, nested and no-styling cases; check partial replacement for JavaScript adapters. The Staff Bulletin and data-panel fixes cover these structures, but other component adapters still need their own validation.

03 / FOUNDATIONS

Brand once. Reuse everywhere.

Five brand seeds feed palette ramps. Semantic tokens name each colour's purpose; component aliases consume those tokens.

Client branding workspace: open Theme-Config.html — Brand studio for one set of five editable seed swatches, optional searchable overrides and one component example at a time. The thin strip below the controls shows the derived palette. Member overview, dummy IQA, native CCO tabs, forms/feedback and Actions all use the shared theme. This implemented, standalone editor is separate from the production theme runtime; persistence and deployment are deferred.

The config page works offline as a single HTML file in the top-level THeme/UnionSuite folder. Edit a colour picker or hex field for immediate styling. In Fine-tune your theme, empty fields follow the source defaults; an entered value pins a token. Clear a field or use its reset button to restore inheritance. Individual overrides cover palette/status colours, semantic aliases, typography, spacing, layout, checkbox/radio colours, and banner/IQA/Actions aliases. Semantic pins intentionally detach from their palette; prefer seeds and palette stops for normal branding.

Sample links stay inside their component example: fragment links scroll locally, unconnected destinations do not navigate, and the dummy IQA can still download its CSV. Preview-only navigation handling prevents the config file from opening inside its own frame. If an old preview has already done this, reload Theme-Config.html after rebuilding.

All config examples receive the same validated stylesheet, including hidden or later-loaded frames. Invalid CSS or circular/unknown token references retain the last valid preview and show a field error. Root tokens apply on :root; banner aliases apply to .us-banner, IQA aliases to report/native-panel wrappers, and Actions aliases to .us-actions, after shared CSS. The Your branding CSS block includes only active valid overrides, with Copy. Nothing is stored, submitted or written to the client stylesheet. Reload discards edits; Reset colours, Clear overrides and Reset everything provide separate reset scopes.

Preview options demonstrate us-banner-sticky or us-banner-collapsible on the overview banner wrapper, us-filters-collapsed and optional us-report-expandable on the dummy report wrapper. These switches call shared refresh APIs and are excluded from the CSS output. Checkbox/radio selectors instead write --checkbox-colour / --radio-colour as var(--accent) or var(--brand-600). CCOs use implemented V5/H2 styling; fixture panel switching and dummy IQA data remain in guide sources. Preview tabs support arrows, Home/End and keyboard focus; native/shared controls retain their accessibility and reduced-motion behaviour. Layout tokens affect only actual consumers, and this is not a full staff-site shell or a live iMIS integration test.

How to update the brand

  1. Use Theme-Config.html to generate branding CSS, or edit the :root seed block in UnionSuite-Client/Branding.css. Keep separately maintained client rules in UnionSuite-Client/Override.css.
  2. Update the existing a.logo rule with the client's image URL, width and height. The logo is an image asset, not a colour token.
  3. Keep status colours deliberate. Success, warning, danger and info are independently defined, so changing the brand does not change their meaning.
  4. Check text, links, focus rings, status badges and hover states on their actual backgrounds. Seed derivation does not guarantee accessible contrast for an arbitrary palette.
  5. Deploy the changed client stylesheet, refresh cached assets, verify the rendered site, and rebuild this guide.

Browsers supporting color-mix() calculate the ramps from the seeds. Older browsers use the predefined Orion palette. The current client file has a logo rule and no active colour overrides.

Tokens affect consumers of those tokens. Current reports, banners and the documented native action buttons use them. Other legacy or native rules with hard-coded colours do not automatically rebrand merely because the tokens exist.

The execution route

  1. Discover: identify the authored control or generated heading slot and its definition. Unconfigured/conflicted controls remain unavailable.
  2. Resolve and validate: read this instance's declared context; check required values, dependencies, eligibility and access.
  3. Claim: prevent duplicate activation for this action/record, including another visible instance.
  4. Confirm: ask only if configured. Cancellation releases the claim without executing or refreshing.
  5. Execute: recheck context/configuration; invoke exactly one operation. A function must return the promise for its actual work.
  6. Observe: wait for the function result or the native popup's close. Closing includes Cancel/X; it is not a universal saved signal.
  7. Refresh: await the target plan or custom callback after the configured event. Keep a successful operation distinct from a failed refresh.
  8. Finish: clear busy/record guards, preserve native focus behaviour and announce errors or configured success. A refresh-only retry never repeats the operation.

Gotcha: outer row gutters can widen the whole page

Native .row uses negative horizontal margins, balanced by half-gutter padding on its columns and the surrounding layout. UltraWave defines --bs-gutter-x:30px; the project Orion foundation keeps a 40px general default and uses 24px for standard page-layout rows. Those layout rows extend 12px beyond each side of their immediate wrapper; ordinary 40px rows extend 20px. Clearing the surrounding horizontal padding, moving a row to an unpadded shell, or embedding it in an iframe breaks this balance even when every width is 100%.

Native CCOThe theme's .RadMultiPage padding and the content row share one document, allowing the padding to accommodate the negative margins.
