Scroll with the main page

The custom CCO automatically grows to its selected page's content height, so the main page scrolls as it does for a native CCO. Its iframe still fills the available content-column width and retains the native child page and form state. Install the rebuilt upload/UnionSuite-CCO.zip at the existing ZIP location and reload the containing page. Keep the same display/configure paths. No new author class or configuration setting is required; the runtime supplies .us-cco__frame itself.

Height is remeasured after content updates, images/fonts loading, responsive reflow, child navigation and tab reveal. Content can shrink as well as grow. Hidden preloads wait for a measurable width; returning to a tab preserves its frame. Observers are removed on reload, partial replacement and disposal. The existing first-visible loading delay and accessible loading announcements remain.

The runtime removes viewport height/minimums from the child document's html/body and contains body floats to measure natural height without changing its form structure. Explicit scrolling regions inside native grids/editors remain native. Viewport-sized child widgets and fixed-position content may need their own sizing integration; verify these on the deployed iMIS pages. The same-origin requirement and existing error/retry handling still apply.

Gotcha: outer row gutters inside an iframe

The native CCO puts its content row in the same document as the padded .RadMultiPage. In the custom CCO, that padding sits outside the iframe. The native empty-page shell has zero horizontal padding, leaving the child page's outer row margins unbalanced. UltraWave starts with a 30px gutter; Orion sets --bs-gutter-x:40px, making the row extend 20px past each side. A 984px viewport then contains a 1024px row and 20px of right-side overflow. Width normalization alone cannot correct this.

The child stylesheet clears only margin-left and margin-right on the page layout's outer row. The supported structure is :is(.ContentWizardDisplay, .ContentPanel, .EmptyMasterContentPanel) > div > .row. The owner and row must be outside component roots and descendants of .ContentItemContainer, .iMIS-WebPart, .RadGrid and .RadWindow. A direct layout div with .container or .container-fluid is excluded because it already supplies balancing padding. Column padding, vertical margins, the gutter token and nested field/iPart rows remain native.

Install the rebuilt upload/UnionSuite-CCO.zip at the current upload location and reload the containing page. No author class, HTML, token, new setting or shared-theme stylesheet upload is required. The correction is maintained in src/frame-size.js. It applies to newly replaced layout nodes automatically and is reinstalled on child navigation or refresh; frame cleanup removes the injected stylesheet. Existing form nodes and retained tab state stay in place.

node tests/frame-gutters.cjs first reproduces the 20px overflow with the real CSS cascade. It then checks three outer shell variants at parent widths of 390, 900, 1280 and 1480px, direct/classed/empty iPart wrappers, no-panel content, nested field/iPart gutters, balanced containers, native grid scrolling, retained inputs, partial replacement, refresh and stable height. Custom templates with a different outer layout structure may need a scoped adapter. The fix does not hide horizontal overflow; custom fixed-width widgets still need responsive styling. Native integration and verification

src/page-editor.js builds the same-origin AsiCommon/Controls/ContentManagement/ContentDesigner/ContentRecordEdit.aspx route beneath __ClientContext.websiteRoot, then gWebSiteRoot, then the application root as fallback. It passes this tab's DocumentVersionId as iUniformKey, with Mode=Maximized, iOperation=Edit, TemplateType=E and DocumentTypeCode=CON. No tenant hostname or example page key is hard-coded.

The supplied native SetupRadWindow probe confirms argument 8 is beforeClose and argument 12 is close. The former is left empty; the latter schedules refresh/focus after native close handling. ShowDialog_NoReturnValue does not return the window. The preview child remains in Execute mode: this feature opens the whole-page editor rather than adding Easy Edit controls to preview HTML.

src/runtime.js owns visibility, lifecycle guards and refresh. A boolean parent gIsEasyEditEnabled is authoritative, with native Easy Edit body/toggle markers as fallback when absent. Native page loads, ASP.NET updates and marker changes reconcile visibility. A custom integration that changes only the global flag can call window.UnionSuiteCCO.scan().
