Egg suppressed — nothing run yet

This is the actual risk in the category. A joke printed on top of a silent load failure tells a staff member there is no work when there is — and they will believe it, because the system sounded confident. The egg needs a positive signal that a query completed and returned zero; absence of rows is not that signal. If the component cannot tell the three apart reliably, it renders the plain state and no egg at all.

C3 — same query run repeatedly Recorded with the copy changed. Read the note.

Query results — Pending direct debit returns

Run 4 of 4 · 3 members
✦

Still the same.  →  Same as it was.

(Results would render here as normal.)

Why the copy changed. Staff re-run a query precisely because they expect the answer to change — a payment to land, an import to finish, an approval to clear. "Still the same" asserts that nothing changed. If three rows became three different rows, the system has just told a confident lie to someone concentrating. "Same as it was" is said about the page, claims nothing about the data, and keeps the joke. Either that, or compare a hash of the result set rather than the count — but the copy fix is free. Cap it at the third or fourth identical run, once per session, then never again.
