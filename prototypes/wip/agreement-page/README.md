# Agreement page (Manage Agreement)

Status: WIP, started 2 October 2026. Not yet approved.

## Problem

The Manage Agreement test page in iMIS (`/Agreements_ManageAgreement`) was
built before the UnionSuite theme. It carries its own palette, card and
banner CSS, a custom right-hand accordion with tab panels and scroll spy,
and about 1,600 lines of JavaScript delivered through two IQA iParts
(`ciIQACSS`, `ciIQAJS`). The list content is rendered into hidden
`RawTemplate` iParts and cloned into place by script.

This folder rebuilds the page from the shared theme (the contact page v2/v3
playbook). The existing IQAs stay as they are; only the Query Template HTML,
iPart settings and page layout change (owner, 2 October 2026).

Sources: the original mock-up is `prototypes/Agreement Management/` (v1);
the live page HTML and JS were supplied by the owner on 2 October 2026.

## Preview

Start the `static-node` configuration in `.claude/launch.json` (port 8778),
then open:

```text
http://localhost:8778/prototypes/wip/agreement-page/index.html
```

The page needs the server: the sample rows are rendered by fetching the real
author templates in `templates/` and filling their `{#query.Field}` tokens.
A template that references a field the sample row lacks fails loudly, as a
reminder that the IQA must select every referenced field.

Toolbar (prototype only):

| Control | Effect |
| --- | --- |
| Saves: succeed / fail | Makes the offline CloudToolz endpoints answer 500, to show task, milestone and attachment save failures. |
| Mode: light / dark | The theme's own `UnionSuiteAppearance.toggle()`. |

Fixtures: CloudToolz, ZenTokens and the tag IQA are answered offline by
`agreement-page.js`. The native popup is replaced by a toast naming the page
it would open; its close callback runs, so the in-place refresh is exercised.
"Today" is pinned to 2 October 2026 for past and upcoming meetings.

## Building it in iMIS

1. Load the candidate CSS/JS in the theme (or test them on the page first).
2. Replace the two banner iParts with one Query Template Display on the
   Banner primary IQA using `templates/Agreement-Banner-Query-Template.html`,
   and create the banner details IQA (see open decision 1).
3. Add one CCO (Vertical right, CSS class `us-cco-sticky-tabs us-cco-rail`)
   with tabs Overview, Activity, Coverage, Terms & Schedule and Reports.
4. On each tab, add the iParts listed in `index.html` with the CSS class
   and template in the comment above each one. Set the native titles.
   Header/Footer blank unless the template header says otherwise.
5. Point each Query Template Display at its existing IQA, filtered by the
   `AgreementNum` URL parameter. The old hidden Tasks iPart listed tasks from
   other agreements, so check that filter on Tasks especially.
6. Remove the anchor Content iParts, `ciIQACSS`, `ciIQAJS`, the `RawData` and
   `RawTemplate` iParts and the `#data-div` zone.
