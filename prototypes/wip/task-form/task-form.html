Task form

One task form, three modules

  1. One form, three pages. Each page holds only a placeholder; the form is drawn by the shared script. The page fixes the module and its tag filter.
  2. The record line says where the task is going. From ModuleID at once, and the record's name from an optional IQA on the placeholder. Personal tasks say so.
  3. Personal tasks are the signed-in user's own (owner, 19 October 2026): always assigned to the signed-in user, so there is no Assign to field; the record line says so.
  4. Tags come from the task tag IQA, filtered by the page's module (optional), so each module shows its own list; shared tags such as Correspondence show everywhere. Subtags follow the chosen tags by parent ordinal alone. With no task tags set up the row is not drawn.
  5. Due date, then Assign to: the date starts empty and is what people set; the assignee starts as you. Assign to has its own list per module (owner, 19 October 2026): cases, the case's staff; agreements, all staff or the agreement's staff, set on the page's placeholder (data-assign; toolbar: Agreement assign list). Optional on cases and agreements: an unassigned task belongs to the record itself. It starts as you; clear it to leave it unassigned.
  6. Edit is the same form, opened with Ordinal (unique within its module): filled in, details open when there are any, Completed to tick off (or reopen) the task, Save changes, no Save and add another, and who added it. No Delete: admin only, v2.
  7. Save and add another saves, keeps the form open and clears the task line, details and flag; the assignee, due date and tags stay for the next one, and a line says what was saved.
  8. No theme: the form brings its own styles and icons and reads the theme's colours only when they are there.
