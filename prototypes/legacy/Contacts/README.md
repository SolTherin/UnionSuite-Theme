# Shared workplace contact reference

The approved contact mockup is now supplied by the shared theme. This page demonstrates the canonical Contacts-Query-Template.html in native Query Template Display wrappers.

- Build: `node tools/build-contact-preview.cjs`; verify generated output with `--check`.
- Output: `references/Contact-Lists-Preview.html` (standalone/offline).
- Shared theme: native panel/header/description, `us-query-search`, `us-badge`, `us-contact`, `us-list-scroll`, buttons and tokens. Contact/scroll behaviour is in zUnionSuite.js; component CSS is in zUnionSuite.css. Load the existing Tabler stylesheet/font for icons.
- Use `us-query-search us-list-scroll` in the iPart CSS class field, with a nonempty Title and Display in cards unchecked. Paste Contacts-Query-Template.html into the repeating Query Template field; Header/Footer can stay blank. The `us-contact` article belongs inside the result; the iPart setting creates the outer class wrapper.
- Page composition lives in contacts-preview.html. Its adjacent CSS/JS now contain only preview layout, width controls and sample profile dialogs. The builder reads the canonical template and docs/contact-records.cjs sample data.
- Search is independent per list. Fade clears at the bottom, when no overflow exists, and after filtering. Headers remain outside the scroll area. Coarse and narrow screens retain native keyboard navigation and individually actionable links.
- Badge text uses sentence case at 12px. RoleColour supplies any #RGB or #RRGGBB background; text automatically uses black or white for greater contrast. Blank/invalid colours use neutral theme colours. No named-role palette is applied.
- Empty badges/contact details are omitted. Long text wraps; one contact detail spans the row; narrow cards stack details.
- Name/workplace destinations are local sample dialogs. Email/phone links use illustrative example.org addresses and sample numbers. No API, persistence, or live contact data lookup.
- `data-us-search` explicitly includes contact name, role label, workplace, email, phone and ContactId; remove it to fall back to visible-text search. IDs are not printed but remain readable in page HTML. Empty overrides do not fall back. Search remains case-insensitive substring matching with whitespace normalisation; no API calls or phone normalisation.
- Every field referenced in the template must be included in the IQA Select/display column list with a matching output alias, including fields in links and data-us-search. The unchanged contact template needs all nine aliases selected. Only ContactName needs a nonempty value. For an unused optional field, add a selected custom SQL column with expression `''` (two single quotes) and the matching alias, or remove every reference from the template, including its relevant optional block, links and search tokens. For example, keep Email selected with expression `''`, or remove both the email detail block and its search token. “Optional” permits a blank value; it does not permit omitting a still-referenced column. Shared JS hides rendered empty rows/badges but cannot satisfy a missing selected query column.
- RoleColour/RoleLabel and URL/name/email/phone fields are suggested IQA output aliases; map your actual selected columns to them. Shared JS leaves invalid/blank profile destinations as plain text. Keep all substitutions HTML-encoded. RoleColour replaces the previous RoleKey alias: paste the updated template using data-us-contact-colour, with a hex value such as #DBEAFE. Existing iPart classes are unchanged. Named/alpha colours and CSS functions are rejected; optional surrounding whitespace and mixed hex case are supported.
- The independent scroll helper uses --us-list-max-height (414px default), updates its fade as content changes, preserves author accessibility attributes and cleans up on replacement/opt-out. Authored Header/Footer and native pager inside the body scroll with results; panel heading/description and search stay outside.
- Author recipes and mapping are in Usage-Guide.html#contact-lists and references/List-Templates.html. Regression coverage: tools/test-contact-lists.cjs and tools/test-query-search.cjs.
